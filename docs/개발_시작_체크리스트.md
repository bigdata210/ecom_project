# 웹 플랫폼 개발 시작 순서

대상 저장소: https://github.com/bigdata210/ecom_project.git

이 문서는 기존 데스크톱 변환 코드를 보존하면서 웹 플랫폼을 준비하기 위한 순서다. Git 원격 주소 등록, GitHub 접근 확인, 소스 푸시, Vercel 연결, 운영 배포는 서로 다른 단계다. 원격 주소를 등록했다고 소스 업로드나 홈페이지 공개가 완료되는 것은 아니다.

## 1. GitHub 연결

- 로컬 Git의 origin에 지정 저장소를 등록한다.
- GitHub 접근 후 기본 브랜치·기존 파일·저장소 공개 범위를 확인한다.
- 기존 파일이 있으면 내용을 먼저 가져와 비교한다. 강제 푸시로 덮어쓰지 않는다.
- 원본 PDF·고객 Excel·결과 파일·API 키는 제외하고 코드를 검토해 첫 커밋과 푸시를 진행한다.
- 현재 `.gitignore`는 고객 문서, 템플릿 바이너리, 로컬 의존성, 빌드·결과 파일을 제외한다. 향후 테스트에는 비식별 자료만 명시적으로 추가한다.

## 2. 홈페이지 첫 구현

- 계획안과 시안에 맞춘 한국어 대시보드와 변환·검수 화면부터 구현한다.
- 웹은 Next.js/TypeScript를 기본안으로 하고 기존 Python 처리는 별도 서버로 옮긴다.
- 초기에 화면 예시 데이터와 실제 저장·변환 기능을 구분한다. 연결되지 않은 기능을 실제 운영 기능으로 표시하지 않는다.
- Vercel 프로젝트가 Next.js 앱의 폴더를 기준으로 빌드하도록 Root Directory를 설정한다. 현재 Python 프로젝트 폴더 전체를 Next.js 앱으로 간주하지 않는다.

## 3. Vercel 계정 연결

- Vercel에서 GitHub 계정에 연결하고 해당 저장소의 접근을 허용한다.
- 웹 소스 준비 후 저장소를 Import하고 웹 앱 경로를 지정한다.
- 먼저 Preview 배포에서 확인한 뒤 운영 브랜치를 연결한다.
- 개발·미리보기·운영 환경의 비밀값과 DB를 분리한다.
- Vercel 로그인 정보나 GitHub 토큰을 채팅에 전달하지 않는다. 각 서비스의 공식 연결 화면에서 인증한다.

## 4. 로그인·DB·파일 저장

- 인증/DB 공급자와 계정을 결정한다. 기존 제안은 Supabase 또는 별도 인증+PostgreSQL+비공개 스토리지다.
- 관리자·검수자·측정원과 업체 멤버십을 정의한다.
- 원본, 검수 초안, 확정 데이터, 출력 양식을 구분해 저장한다.
- 업체별 DB·파일 접근 제어를 먼저 검증한다.

## 5. LLM·처리 서버

- 외부 AI 전송 범위와 동의 방식을 정한다.
- LLM API 키는 서버의 Secret/환경변수에만 등록한다.
- 기존 PDF 추출·Excel 작성 코드를 서버에서 실행하고, 긴 작업은 대기열로 처리한다.
- LLM은 표준 구조 추출·매핑 제안에 사용하고 확정은 사람의 검수를 거친다.

## 6. 실제 운영 자료와 비용

- 비식별 PDF 및 수작업 정답, 빈 Excel 양식을 확보한다.
- 업무상 계산·단위·ND 처리·결과 파일 분리 규칙을 확정한다.
- 파일 수·페이지 수·동시 사용자·보관기간·월 예산을 정한다.
- 이후 추이 분석과 기상청 연결을 추가한다. 공개 서비스 가입·과금은 시범 운영 검증 후 진행한다.

## 다음에 한 번에 확인할 내용

먼저 GitHub 저장소에 정상 접근할 수 있어야 기존 소스를 확인하고 안전하게 동기화할 수 있다. 그다음 Vercel 계정 보유 여부와 해당 저장소 Import 권한을 확인한다. API 키는 이 단계에서 필요하지 않다.
